- pokrenuti bat skriptu na windows ili sh skriptu na linux da bi se instalirali modeli (models/ nije u gitu)
- video snimak iz cabin camera staviti tamo gde je risk_pipeline.py fajl (ili dati punu putanju)

DVA MODA

1) DEV (podrazumevano): video sa metrikama, za razvoj i podesavanje modela
   python risk_pipeline.py --video snimak.mp4

   Levo video: lice vozaca (narandzasto = pogled van puta) + strelica glave, ruke (zelena = na volanu,
   narandzasta = van), telefon (YOLO), ivica u boji alarma. Desno samo najbitnije: alarm i rizik,
   pravila koja su opalila, kategorije (traka = p_hat, crtica = prag, ON + trajanje), signali
   (glava vs put, oci, ruke, telefon) i rizik poslednjih 30 s.
   Tasteri: SPACE pauza, R prikazi ROI-jeve, S screenshot (u logs/<sesija>/), Q ili ESC izlaz.
   Na kraju: izvestaj cele voznje (racuna ga backend kod, backend/app/services/model_report.py,
   isti koji ide u aplikaciju) i logs/<sesija>/frames.jsonl + run.json.

   Korisne opcije:
     --verbose              jedan red po obradjenom frejmu u terminalu (sve promenljive)
     --save-video out.mp4   snimi prikaz (video + panel) u fajl;  --no-show = bez prozora
     --log-all              frames.jsonl za svaki obradjeni frejm (inace 5 Hz)
     --start 12 --max-seconds 10   samo deo snimka
     --backend [URL]        uz prikaz salji i backendu (kao prod);  --realtime = brzinom snimka

2) PROD (za debug): bez prozora i bez prikaza, salje backendu
   Napomena: pravi put u kolima je kamera -> koordinator -> model/worker.py, i rizik tada racuna
   koordinator (docs/ARCHITECTURE.md). Ovaj mod sam racuna rizik i sluzi za debug i poredjenje.
   Dok je model worker povezan, backend odbija ove zapise (409).
   python risk_pipeline.py --video 0 --mode prod                    (kamera 0 -> backend sa configa)
   python risk_pipeline.py --video snimak.mp4 --mode prod --start-trip demo   (snimak, bez telefona)

   Salje zapis frejma na POST /telemetry (~2/s i odmah na svaku promenu alarma) i JPEG frejmove na
   POST /video/frames (za klipove rizicnih momenata). Mreza radi u pozadinskim nitima, pa spor ili
   ugasen backend ne usporava kameru. Snimak ide brzinom snimanja kao prava kamera (--no-realtime
   da ide najbrze). Na ~10 s ispise stanje (alarm, ms po frejmu, koliko je poslato, score).
   Rezime vozne, epizode i alarme racuna backend: GET /trips/{id}/report, polje "model".
   Voznju inace pokrece aplikacija; bez nje backend vraca 409 i zapisi se odbacuju (vidi se u stanju).
   --backend URL  druga adresa backenda (podrazumevano backend.url u risk_config.json)
   --no-video     bez videa;  --log  i lokalni frames.jsonl (ono sto ide backendu)

Izvestaj za vec snimljen frames.jsonl (iz backend/ foldera, venv backenda):
   python -m app.services.model_report ..\notebooks\logs\<sesija>\frames.jsonl [--json]
Replay snimljenog frames.jsonl u backend (bez modela):
   python safety_client.py --replay logs\<sesija>\frames.jsonl

Podesavanje za novu kameru / novi polozaj kamere (jednom, upisuje se u risk_config.json):
  1) ROI:        python risk_pipeline.py --video snimak.mp4 --pick-roi [--at 5]
                 redom se mišem oznace driver_roi (ceo vozac), head_roi (glava), steering_wheel_roi (volan)
                 ENTER/SPACE = sacuvaj, C = zadrzi postojeci
  2) Kalibracija: python risk_pipeline.py --video snimak_normalne_voznje.mp4 --calibrate
                 meri pozu glave "gleda u put" i upisuje calibration.prior_yaw_deg / prior_pitch_deg
  Za Rivian dataset (kamera gleda unazad, vozac je DESNO na slici) vrednosti su vec podesene.
