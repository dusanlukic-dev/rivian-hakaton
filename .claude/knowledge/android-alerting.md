# Android alerting: sound, flash, vibration, wake from sleep

The goal is to get a distracted driver's attention **immediately and reliably**, whatever state the phone is in.
Target device: Galaxy A54 (One UI). Android only, see `decisions.md` D11 for iOS.

## Library roles (all native modules are already in the dev build)

|---|---|---|

expo-notifications copies them to `res/raw`, so a channel `sound` is the file name **with** `.wav` for expo-notifications and the raw
name **without** an extension for notify-kit (verify on first use).

## Why the alarm stream matters

A notification-usage sound is **muted when the phone is on vibrate or silent** and follows notification volume. Alarm usage plays in
silent mode, uses alarm volume (usually high), and is allowed by the default Do Not Disturb rules. notify-kit hard-codes
`USAGE_NOTIFICATION` for channels it creates, which is why channel creation goes through expo-notifications.
A channel's sound and importance are **immutable after creation**. To change them, use a new channel id (e.g. `alerts_v2`),
or reinstall or clear app data.

## Triggers come from the backend, never from the app's own logic

Every WS `state` (~1/s) carries `response = { dashboard_light, vibrate_seat, sound: none|low|high, message }`, and an `emergency`
event arrives once per trip when the score drops below 10. The app **executes** these and never decides on its own (docs/API.md §7).
The full field → effect table is in `metrics-and-scoring.md`.

## Foreground mode (main demo path)

App open on the Drive screen with `useKeepAwake()`. The background colour is `dashboard_light`.

- `vibrate_seat` → `Vibration.vibrate(300)` per message. `sound: low` → `chime` per message.
- `sound: high` → `alarm_warning` per message + red pulse overlay (≤ 2 Hz) + brightness up.
- `emergency` → full-screen red pulse + `alarm_critical` loop + continuous vibration + TTS + "Send SMS to <contact>" (proposal) + an "OK" button.
- Optionally **also** post the alarm-channel notification in the foreground. Its sound then uses the alarm stream even when media volume is 0.

## Background / locked mode (stretch, the "wake from sleep" requirement)

1. **Keep the process and socket alive:** when Drive mode starts, show a notify-kit notification with `asForegroundService: true`
   (ongoing "Drive mode active"). Manifest types: `location` (Doze-exempt, no timeout; needs a runtime location permission, and the
   phone's GPS speed is a real input) and `specialUse` as a fallback. Pass `foregroundServiceTypes` at start, then keep the
   WebSocket in JS. The RN JS thread keeps running while the process is alive.
2. **Alert** (on `sound: high` or the `emergency` event): `displayNotification({ android: { channelId: 'alerts_critical', category: AndroidCategory.ALARM, importance: HIGH,
   fullScreenAction: { id: 'default' }, loopSound: true, ongoing: true, actions: [{ title: "I'm focused", pressAction: { id: 'ack' } }],
   smallIcon: 'ic_stat_alert' } })`.
   - `fullScreenAction` + `showWhenLocked`/`turnScreenOn`: when the phone is **locked or screen-off**, Android launches the
     activity full-screen and wakes the display. When the phone is **unlocked and in use**, Android shows a heads-up notification instead (OS rule).
   - `loopSound` sets FLAG_INSISTENT: the sound repeats until the notification is cancelled. Cancel it on clear/ack.
3. **Bring the app to the front while the driver uses another app** (they're on Instagram, say): with "Display over other apps"
   (`SYSTEM_ALERT_WINDOW`) granted, Android allows activity starts from the background. `Linking.openURL('driveralert://alert')`
   should then pop the alert screen over the other app. Unverified, test it.

## Permissions and special access (demo-phone prep)

Runtime (the app requests these): `POST_NOTIFICATIONS`, `ACCESS_FINE_LOCATION`, `CAMERA` (QR scan only).
Special access (Settings toggles, so the app deep-links with expo-intent-launcher):
- **Full-screen notifications** (Android 14+ restricts `USE_FULL_SCREEN_INTENT` to call/alarm apps). Check with
  `notifee.getNotificationSettings()` → `android.fullScreenIntent`.
- **Display over other apps** (`SYSTEM_ALERT_WINDOW`).
- **Do Not Disturb access**, so the channel can `bypassDnd`.
- **Battery: Unrestricted.** Samsung pauses foreground services after a few seconds with the screen off on battery otherwise
  (notify-kit README, notifee#410). Settings → Apps → Safety Reviewer → Battery → **Unrestricted**. Also make sure it isn't in
  Settings → Battery → Background usage limits → Sleeping / Deep sleeping apps. https://dontkillmyapp.com/samsung

Faster for the demo phone over adb (package `dev.hakaton.driveralert`; verify each on first use):

```bash
P=dev.hakaton.driveralert
adb shell pm grant $P android.permission.POST_NOTIFICATIONS
adb shell pm grant $P android.permission.ACCESS_FINE_LOCATION
adb shell pm grant $P android.permission.CAMERA
adb shell appops set $P SYSTEM_ALERT_WINDOW allow
adb shell appops set $P USE_FULL_SCREEN_INTENT allow
adb shell cmd notification allow_dnd $P
adb shell dumpsys deviceidle whitelist +$P
adb shell cmd appops set $P RUN_ANY_IN_BACKGROUND allow
```

## Settings intents, verified on the A54 (One UI 8 / Android 16), 2026-11-06 evening

| row | intent (data `package:dev.hakaton.driveralert`) | opens |
|---|---|---|
| notifications | `notifee.requestPermission()`, else `notifee.openNotificationSettings()` | system prompt / the app's notification page |
| full-screen alerts | `android.settings.MANAGE_APP_USE_FULL_SCREEN_INTENT` | the app's "Full screen alerts" switch |
| battery | `android.settings.REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | system dialog for this app (manifest has the permission); closes at once if already unrestricted |
| DND | `android.settings.NOTIFICATION_POLICY_ACCESS_DETAIL_SETTINGS` | the app's "Do not disturb permission" switch |
| fallback | `android.settings.APPLICATION_DETAILS_SETTINGS` | App info |

- The first version opened `IGNORE_BATTERY_OPTIMIZATION_SETTINGS` (notify-kit's helper: the list of all apps) and
  `NOTIFICATION_POLICY_ACCESS_SETTINGS` (all apps' DND list). That was the "it opens only the default page" report: our code,
  not the dev build. The package name is the same in dev and release.
- `startActivityAsync` resolves when the settings page is closed, and the app also re-checks on every return to the foreground
  (`state/permissions.ts`), so ticks update without leaving the tab. DND access can't be read by any installed library
  (`isNotificationPolicyAccessGranted` would need a small native module), so that row always shows "Open".
- `expo-keep-awake` activate/deactivate **reject** when the Activity is gone (swipe-away during a trip: the foreground service keeps
  JS alive and the Drive screen unmounts later). The calls now have `.catch`.
