# Dashboard rules (project-specific)

The stack rules (imports, Hugeicons, shadcn, one-component-per-folder, React Compiler lint rules, gotchas) are in
`frontend/dashboard/CLAUDE.md`, which carries over from the user's hackathon starter. This file adds what is specific to this project.
Workflow: skill `dashboard-dev`.

- **Purpose:** a mock of the car's centre screen. It shows speed, assist mode, one icon + bar per metric (driven by data, so unknown metric
  keys still render), the risk level, and the red pulse + beeps on warnings. It also hosts the **sim panel** (scenario buttons and sliders
  that send `sim` messages) and a **QR code** of the `ws://` URL so the phone can connect. Contract: `.claude/knowledge/ws-protocol.md`.
- **Transport:** plain WebSocket. The starter's `useSignalR` / `@microsoft/signalr` is legacy here. Replace it with a `useCarSocket`
  hook that keeps the same never-give-up retry semantics, then remove the SignalR dependency and update the showcase page.
- **One adapter:** wire format → internal model only in `src/protocol/normalize.ts`. Keep it equivalent to the mobile one.
- **Sound:** browsers block audio until a user gesture, so put an "Arm sound" button / first-click unlock before the demo. The WAVs
  live in `public/sounds/`, generated by `node tools/gen-sounds.mjs`. Web Audio oscillators are fine too.
- **Flashing ≤ 3 Hz** (D14). Use theme tokens. Red alert colours go in CSS variables, not hardcoded in components.
- In dev, `/api` and `/hubs` proxy to `VITE_API_URL` (see `vite.config.ts`). The WebSocket path is `/api/v1/ws`, so the `/api` proxy
  rule needs `ws: true` once we use it.
- **Done means:** `npm run build` and `npm run lint` pass in `frontend/dashboard`, plus a headless-Chrome screenshot check for visual changes.
