# Mobile app rules (Expo SDK 58 · RN 0.88 · React 19.3 · TypeScript 6 · New Architecture only)

Also follow `frontend/mobile/AGENTS.md` (Expo's official agent notes). **Expo changes every SDK, so check APIs against
https://docs.expo.dev/versions/v58.0.0/ and https://docs.expo.dev/llms.txt instead of memory.** Workflow: skill `mobile-dev`.

- **Dev build, not Expo Go.** Native modules we use aren't in Expo Go.
- **Dependencies:** always `npx expo install <pkg>`. Adding or removing a native module, or changing `app.json` plugins or permissions, is
  a **native change**: run `npm run prebuild` then `npm run android` (rebuild + reinstall). JS/TS-only changes just hot reload.
  Every native module we expect is already installed, so ask before adding another one: it forces a rebuild for everyone.
- **`android/` is generated** (CNG, gitignored). Never hand-edit it. Change `app.json` or a config plugin in `plugins/`, and run
  `npm run prebuild:clean` if the native project looks stale.
- **Routing:** expo-router. Only screens and `_layout.tsx` go in `src/app/`. Everything else lives in `src/` (`protocol/`, `connection/`,
  `alerts/`, `settings/`, `components/`, `hooks/`). The import alias `@/` maps to `src/`.
- **React Compiler is on:** don't hand-write `useMemo`/`useCallback`. Follow the Rules of React (no mutation during render, no
  reading `ref.current` during render).
- **Alerts stack:** `react-native-notify-kit` (default import `notifee`) for notifications, foreground service and full-screen intent.
  `expo-notifications` **only** creates alarm-usage channels. **Never** add `@notifee/react-native` (archived). Details: `.claude/knowledge/android-alerting.md`.
- **Sounds:** `assets/sounds/*.wav`, generated by `node tools/gen-sounds.mjs` (repo root). Raw resource names are `chime`,
  `alarm_warning`, `alarm_critical`. A notification channel's sound is fixed once created, so bump the channel id to change it.
- Audio is `expo-audio` (expo-av no longer exists). TTS is `expo-speech`, screen-on is `expo-keep-awake`, brightness is `expo-brightness`.
- **Networking:** plain `WebSocket` to `ws://host:port/api/v1/ws` (cleartext is allowed by expo-build-properties). Never hardcode an IP.
  It comes from the settings store, and the default is `localhost:8000`, which works over USB with `npm run adb:reverse`.
- **One adapter:** all parsing of backend messages happens in `src/protocol/normalize.ts`. The UI must tolerate any subset of metrics,
  unknown keys and `null` values.
- **UI:** dark-first (in-car), big touch targets, readable at arm's length, English strings. Flashing ≤ 3 Hz (D14).
- **Done means:** `npm run lint` and `npm run typecheck` pass in `frontend/mobile`. If native config changed, also a successful
  `npm run android` on the device and a screenshot check (skill `android-device`).
